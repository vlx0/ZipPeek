# ZipPeek

**Что внутри ZIP и всё ли читается.** Содержимое, размер после распаковки и потоковая проверка CRC без извлечения файлов.

Автор: **darkshade** ([@vlx0](https://github.com/vlx0)). MIT.

**365 дней open source · неделя 12 — «Файлы» · день 84, финал недели.**

## Возможности

- Список записей: имя, исходный и сжатый размер, результат проверки.
- Размер ZIP на диске и суммарный заявленный размер после распаковки.
- Полное чтение записей с проверкой CRC, без создания распакованных файлов.
- Повторяющиеся имена проверяются отдельно, по каждой записи ZIP.
- Фильтр по имени, копирование имени, подробности ошибки выбранной записи.
- Отмена между порциями чтения; результаты остановленной проверки остаются частичными.
- Лимит несжатых данных: 1 / 4 / 16 ГиБ либо без лимита; по умолчанию 4 ГиБ. Если следующая запись не помещается в оставшийся бюджет, проверка останавливается до её чтения.
- Повреждённая запись тоже расходует бюджет по заявленному размеру: ошибка CRC не позволяет обойти лимит.
- Шифрованные записи требуют пароль: эта версия не расшифровывает их и не выдаёт им статус OK. Неподдерживаемые методы сжатия также отмечаются отдельно.
- Пустой ZIP корректно распознаётся; битый каталог архива выдаёт ошибку открытия.
- Фоновое чтение, тёмный интерфейс на русском, один экземпляр на сеанс Windows (mutex).

Открытие списка ещё не проверяет данные файлов. Глубокая проверка больших ZIP нагружает диск и CPU; она запускается отдельно кнопкой «Проверить целостность».

CRC проверяет целостность содержимого, а не подлинность или безопасность файлов. Файлы внутри архива не открываются и не выполняются. Суммарный размер до проверки берётся из заголовков ZIP. При изменении архива нужно открыть его заново.

## Запуск

Windows 10+, Python 3.10+ с tkinter. Внешних зависимостей нет.

```powershell
pythonw -m zippeek
```

Или `start.bat` / `run_zippeek.pyw`.

Настройки: `%APPDATA%\ZipPeek\settings.json` — последний путь и лимит чтения.
